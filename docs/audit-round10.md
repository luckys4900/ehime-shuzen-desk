## 新規の指摘

### R10-1（P2）本番接続時の送信失敗の表示が消える／通信断で何も表示されない
- **場所**: `src/assets/main.js`
  - `showStatus()` の `if (type === 'error') box.setAttribute('data-live', '');`
  - 送信処理の `submitInquiry(fd).then(...)`（`catch` がない）
- **再現手順**（`ENDPOINT` を設定した状態。監査では配信する JS だけを差し替えて確認）
  1. 全項目を正しく入力して送信し、送信先が 500 を返す → 要約に「送信できませんでした／時間をおいて、もう一度お試しください。」が出る。
  2. 任意の項目（例: その他）にフォーカスして離れる。
- **結果**: 「送信できませんでした」が、**「入力エラーはすべて解消されました。内容をご確認のうえ、送信してください。」に置き換わる**。`role` も `status` に変わる。送信に失敗した事実が画面から消え、利用者は送信済みと誤解しうる。
  - R9 までは、`refreshSummary` が `form-status--error` クラスで判定し、送信失敗の表示も同じクラスだったため、同じ現象が起きていた可能性はある。ただし R10 で `data-live` を「`type === 'error'` のすべて」に付けたことで、送信失敗にも即時更新が明示的に適用される形になった。
- **関連（既存）**: 通信断（`fetch` の reject）では、`TypeError: Failed to fetch` が未処理の Promise 拒否になり、画面には何も表示されない。送信中にボタンを無効にしていないため、連打で二重送信も起こりうる。
- **影響**: デモ（`ENDPOINT = null`）では到達しない。ただし、コメントで「本番では ENDPOINT に送信先を設定」と案内している引き渡し用の経路であり、本番接続した時点で問い合わせの取りこぼしにつながる。
- **修正案**（数行）
  - `data-live` は入力エラーの要約のときだけ付ける。例: `showStatus(form, type, html, live)` の引数を追加し、入力エラーの空送信からだけ `live = true` で呼ぶ。送信失敗は `data-live` なしにする。
  - `submitInquiry(fd).then(...).catch(function () { showStatus(form, 'error', '<h3>送信できませんでした</h3>…'); })` を追加する。
  - 送信中は送信ボタンに `disabled`（または `aria-disabled` と多重送信の防止フラグ）を付け、完了・失敗時に戻す。
  - QA に、`ENDPOINT` を差し替えた状態で「500 → 項目の離脱後も『送信できませんでした』が残る」「通信断で失敗表示が出る」の検査を追加する（`page.route` で JS を差し替える方式で実装できる）。

### 参考（減点なし）
- **デモの完了表示と、その後の項目エラー**: 「入力内容の確認が完了しました」の表示中に項目を空にすると、完了表示と項目のエラーが並ぶ（フォーム C）。本番の送信成功では `form.reset()` されるため実害はなく、デモでも再送信で正しく救済される。気になる場合は、完了表示中に入力があったら要約を隠すとよい。
- **即時更新の読み上げ**: R9 の参考と同じ（件数だけを流す別の `role="status"` 領域に分ける案）。
- **同じ住宅の写真が多い / shop「営業中」が海外のカフェ**: 受け入れ済みの写真素材の制約として減点しない。

## 総評
R9 の唯一の指摘（「すべて解消」表示後の再無効化で要約が戻らない）は、`data-live` 属性による判定と、エラー時のクラスの付け直しで的確に直された。監査者の検証でも、入力の種類を問わず、件数の往復はすべて正しい。拒否ファイルを含む写真まわりも、送信時の判定と即時更新の件数が一致した。全ルート × 全幅の回帰検証で、表示・ナビゲーション・SP 固定 CTA・フォーム・credits・OGP・noindex・真実性のいずれにも退行はない。

一方で、今回の修正は `data-live` を「エラー表示すべて」に付けたため、本番接続時の送信失敗の表示が、項目の離脱だけで「すべて解消」に上書きされる（R10-1）。通信断で何も表示されない既存の問題もある。デモでは到達しないが、本番接続のために引き渡すコードの不具合で、数行で直せるため満点にはしない。

合計は **99 点（±0）** で、最低点もすべて上回り、HARD_FAIL は 0 件である。**合格** とする。R10-1 を直せば 100 点に届く。
