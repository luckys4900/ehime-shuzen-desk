## 新規の指摘

### R9-1（P2）エラーが解消済みと表示された後に、項目を再び無効にしても要約が更新されない
- **場所**: `src/assets/main.js` の `refreshSummary()` 冒頭
  - `if (!box || box.hidden || !box.classList.contains('form-status--error')) return;`
- **再現手順**
  1. contact で空のまま送信する。
  2. 全項目を正しく入力する → 要約が「入力エラーはすべて解消されました。内容をご確認のうえ、送信してください。」に変わる（このとき `form-status--error` クラスが外れる）。
  3. 「ご担当者名」を空にして、フォーカスを外す。
- **結果**: 項目には「この項目は必須です。」が表示される（`is-invalid` = true）。一方、要約は **「入力エラーはすべて解消されました」のまま** になる。再送信すれば正しく 1 件の要約が出るため、誤送信にはならない。
- **原因**: 解消時に `box.className = 'form-status'` にしたため、以降の `refreshSummary` が冒頭の条件で早期に return する。
- **影響**: 画面上に、互いに矛盾する 2 つの表示（要約「すべて解消」と項目のエラー）が並ぶ。頻度は低く、送信時に救済されるため軽微。ただし、R8-1 と同じ「即時更新の要約」の仕組みの不具合であり、直せる。
- **修正案**（数行）
  - 早期 return の条件を、「`hidden` か、送信の完了表示（`form-status--done`）のとき」に変える。または、即時更新中であることを `data-live-summary` などの属性で持ち、その属性で判定する。
  - 0 件 → 1 件以上に戻ったときに、`form-status--error` クラスを付け直す。
  - QA に「全項目を入力 → 1 項目を空にする → 要約の見出しが『（1件）』になる」の検査を追加する。

### 参考（減点なし）
- **`role` の動的な切り替え**: `alert` ↔ `status` の実行時の切り替えは、支援技術によっては反映が遅れることがある。要約の外側に `role="status"` の小さな領域を別に置き、即時更新ではそこに「残り 9 件」などの件数だけを流す方式にすると、読み上げが短くなり、確実性も上がる。現在の実装でも WAI-ARIA の仕様上は正しいため、減点しない。
- **polite 領域での一覧全体の再読み上げ**: 件数が変わるたびに、要約全体（最大 11 項目のリンク一覧）が読み上げ対象になる。上の方式に変えれば併せて解消する。
- **同じ住宅の写真が多い / shop「営業中」が海外のカフェ**: R8 と同じく、受け入れ済みの写真素材の制約の範囲として減点しない。
