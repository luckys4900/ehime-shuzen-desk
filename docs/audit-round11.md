## 新規の指摘

### R11-1（P2）本番接続後、送信成功のあとも写真の選択が残り、次の問い合わせに前の写真が添付される
- **場所**: `src/assets/main.js` の送信処理 `if (res.ok) { showStatus(...); form.reset(); }`
- **原因**: 写真は `input._files`（独自の配列）とサムネイル（`.js-thumbs`）で管理しているが、`form.reset()` はどちらも消さない。
- **再現手順**（`window.EHIME_FORM_ENDPOINT` を設定し、送信先が 200 を返す状態）
  1. 全項目を入力し、写真（room.png）を 1 枚追加して送信する → 「送信しました」。
  2. 画面にはサムネイルと「写真・ファイルを追加する（1件選択中）」が残る。
  3. 別の物件について入力し直して送信する。
- **結果**: 2 回目の送信データにも room.png が含まれる（監査で送信先のリクエスト本文を確認）。利用者は前の物件の写真が付いていることに気づきにくく、**別物件・別案件に写真が混入** する。管理会社が続けて複数物件を相談する使い方では起こりやすい。
- **影響**: デモでは到達しない（`ENDPOINT = null`）。引き渡し用の経路の不具合。
- **修正案**（数行）: 成功時に `form.reset()` に加えて写真の状態を初期化する。例: フォームごとに `form._resetUploads = function () { input._files = []; input._fileError = ''; setError(form, input.name, ''); render(); }` を定義し、成功時に `if (form._resetUploads) form._resetUploads();` を呼ぶ。あわせて `touched` も空にするとよい（reset 後の入力で 1 文字ごとに必須エラーが出るのを防ぐ）。QA の 200 の検査に「成功後にサムネイル 0 件・2 回目の送信に前の写真が含まれない」を追加する。

### R11-2（P3）電話番号のマイナス記号（U+2212）を受け付けない
- **場所**: `src/assets/main.js` の `toHalfWidth`（`/[－ー―‐]/g`）
- 「ハイフンの有無はどちらでも構いません」と案内しているが、`−`（U+2212）や `–`（U+2013）で区切ると形式エラーになる。macOS の日本語入力や、他の書類からの貼り付けで入りうる。
- **修正案**: 置換の対象を `/[－ー―‐−–—]/g` に広げる（または `/[‐-―−ー－]/g`）。QA に 1 件追加する。

### R11-3（P3）kaitori の注記（`small`）で 2 文字だけの最終行
- **場所**: kaitori「工事範囲の決め方」の注記
  - 430px: 「販売に支障がある箇所を中心に、最小限の範囲で検討する／**場合**」
  - 768px: 「資格・登録が必要な工事は、対応できる施工パートナーを手配できる場合に限り／**ます**」
- QA の短い行の検査は `small` を対象にしていないため検出されていない。
- **修正案**: 該当の `small` を QA の対象に加え、文言の調整（例:「最小限の範囲で検討する場合」→「最小限の範囲で直したい場合」など）か、`text-wrap: pretty` を `small` にも適用する。

### 参考（減点なし）
- `window.EHIME_FORM_ENDPOINT` による上書きは検証用として妥当。本番ではコード内の定数（またはビルド時の置換）で設定する旨を `docs/deployment.md` に 1 行足しておくと、引き渡し先が迷わない。
- 句読点込み 3〜4 文字の最終行（partner「せん。」「ます）。」、kaitori「など。」）と credits の「（背景）」は、可読性に影響しないため指摘にとどめない。
- 同じ住宅の写真が多い / shop「営業中」が海外のカフェ: 受け入れ済みの写真素材の制約として減点しない。
